# Pipeline Desk

Компактные виджеты GitLab для Windows 10/11 x64.

## Запуск

Откройте `release/PipelineDesk-win32-x64/PipelineDesk.exe`. Установка и Node.js не нужны. Перемещайте всю папку приложения целиком.

Если вы скачали исходники с GitHub, сначала соберите приложение на Windows: установите Node.js, выполните `npm ci`, затем `npm run package`. Готовый EXE появится по указанному пути.

1. Нажмите **Подключить GitLab**.
2. Введите адрес вашего GitLab: `https://gitlab.com` или HTTPS-адрес собственного сервера, включая подпапку, если она используется. Нажмите **Получить токен**, создайте персональный токен с правом **read_api** и вставьте его один раз. Адрес и вход сохраняются локально; сервер меняется через **Изменить**. Предустановленного сервера нет.
3. Отметьте нужные проекты в списке и нажмите **Добавить**. Есть поиск и загрузка следующей страницы. Через **По ссылке** можно указать отдельную ветку; без неё отслеживается последний пайплайн проекта среди всех веток.
4. Нажмите значок булавки на карточке: откроется отдельный виджет поверх окон. Перемещайте его за название проекта; размер меняется за края окна.

Булавка внутри виджета переключает режим поверх окон. Значок слоёв открывает общую панель. Положение, размер и открытые виджеты сохраняются. Крестик общей панели скрывает её в трей; завершение — через меню иконки в трее → **Выйти**.

В общей панели можно переключить карточки/список, светлую/тёмную тему и фильтр статуса. Клик по номеру пайплайна или этапу открывает задания. История расположена от старых запусков слева к новым справа. Пайплайн и задания открываются в браузере на подключённом GitLab.

Третий переключатель вида в общей панели включает **компактные строки** без подписи ветки. Вверху каждого виджета есть выбор: **Строка**, **Стадии**, **Подробно**. В режиме **Стадии** под каждым проектом видны все этапы с названиями: длинные названия и цепочки переносятся. Нажатие на этап открывает задания. Вид и высота окна для каждого режима сохраняются. Значок внешней ссылки открывает репозиторий.

## Группы

Нажмите **+ Группа**, отметьте состав и нажмите **Создать**. Название необязательно.

- **Проекты** — отдельные репозитории, включая ещё не добавленные в панель.
- **Группы GitLab** — доступные группы и подгруппы с полным путём. Опция **Включая подгруппы** включена по умолчанию.
- **Мои группы** — объединение существующих групп приложения в новую. Можно смешивать все три вида источников; исходные группы сохраняются.

Выберите группу в верхней строке и нажмите **Виджет группы**. Все её репозитории откроются в одном окне поверх остальных; новые виджеты групп показывают стадии по умолчанию. Значок карандаша меняет состав и название; там же можно удалить группу. Проекты при удалении группы остаются в общей панели.

Состав групп GitLab синхронизируется раз в минуту и по кнопке **Обновить**. Новые проекты появляются, вышедшие из группы исчезают из её виджета. При недоступности GitLab сохраняется предыдущий состав с ошибкой. Проекты, встречающиеся в нескольких источниках, не дублируются; отдельные настройки веток сохраняются как отдельные строки. Объединённая группа получает копию ручного состава исходных групп и сохраняет автоматическую синхронизацию их источников GitLab. Операции с группами приложения не изменяют GitLab.

Интервал обновления: 15, 30 или 60 секунд, в настройках → **Дополнительно**. Ветка и последние пайплайны обновляются автоматически. Если GitLab недоступен, последние данные остаются с явной ошибкой и временем получения. Лимит запросов вызывает паузу перед повтором.

## Данные

Первый запуск показывает **демо**, а не актуальное состояние проектов. Все названия, группы, номера пайплайнов, коммиты и статусы вымышлены и не относятся к какой-либо организации. Подключение к вашему GitLab заменяет демонстрацию вашими проектами.

Подключение, проекты, группы, параметры обновления и настройки окон хранятся локально в SQLite: `%APPDATA%/Pipeline Desk/config.sqlite`. Устанавливать SQLite отдельно не нужно: приложение использует встроенный `node:sqlite`. Таблица `settings` содержит параметры, таблица `credentials` — зашифрованный токен в BLOB. Изменения записываются одной транзакцией.

Токен шифруется Windows DPAPI через Electron safeStorage и не передаётся обратно в интерфейс. При первом запуске после обновления данные автоматически переносятся из `settings.json`, включая уже зашифрованный токен. Старый JSON остаётся неизменной резервной копией; после переноса приложение читает и обновляет только SQLite. Отключение удаляет токен из активной базы. При ошибке открытия базы приложение сохраняет исходные файлы и сообщает об ошибке.

Для резервной копии закройте приложение и сохраните всю папку `%APPDATA%/Pipeline Desk`: она также содержит данные ключа шифрования Electron и настройки внешнего вида. Во время работы рядом с базой могут находиться служебные файлы `config.sqlite-wal` и `config.sqlite-shm`. Файлы базы и авторизации исключены из Git.

Приложение выполняет только GET-запросы к GitLab. Запуск, отмена, повтор заданий и деплой не реализованы.

Если в настройках приложения задан `netrcPath`, оно читает запись `machine` только для выбранного сервера. В поле `password` нужен API-токен, обычный пароль GitLab не подходит. Для `login oauth2` используется Bearer, иначе PRIVATE-TOKEN. Запись `default` игнорируется. После успешного импорта токен сохраняется зашифрованным. При первом подключении файл используется автоматически; после ошибки повторные попытки останавливаются. Исправленный файл можно перечитать кнопкой **Повторить из .netrc**. Содержимое файла и его путь не передаются в интерфейс.

Поддерживается один GitLab-сервер за раз, в том числе сервер в подпапке. При смене сервера список проектов заменяется; при отключении токен и список удаляются. Для корпоративного GitLab может потребоваться VPN и доверенный системой сертификат.

Этапы группируются по заданиям и упорядочиваются по первым ID заданий, включая повторные запуски. Для необычных конфигураций с динамически создаваемыми этапами порядок может отличаться от графа GitLab. Дочерние пайплайны показаны как bridge-задания; детали открываются в GitLab.

## Разработка

```powershell
cd pipeline-desk
npm install
npx install-electron
npm start
```

```powershell
npm test
npm run test:ui
node tests/setup.mjs
node tests/groups-ui.mjs
node tests/widget-views.mjs
node tests/full-group-layout.mjs
node tests/storage-electron.mjs
npm run package
npm run preview
```

Предпросмотр: `http://127.0.0.1:4317/ui/index.html`. В браузере доступны демонстрация и просмотр виджета; настоящее закрепление и GitLab работают в Windows-приложении.

Проверки API используют фикстуры: повторные задания, optional failures, manual/canceled, пагинация, read-only запросы, неверный токен и rate limit. Electron-проверки охватывают интерфейс, настоящие окна, закрепление, восстановление, защищённое сохранение токена, импорт .netrc, поиск и массовый выбор проектов. Успешное подключение к реальному GitLab требует действующего API-токена.

API: [GitLab pipelines](https://docs.gitlab.com/api/pipelines/), [GitLab jobs](https://docs.gitlab.com/api/jobs/), [GitLab groups](https://docs.gitlab.com/api/groups/), [personal access tokens](https://docs.gitlab.com/user/profile/personal_access_tokens/), [Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage), [Node.js SQLite](https://nodejs.org/api/sqlite.html).
