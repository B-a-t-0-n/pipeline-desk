# Pipeline Desk

Компактные виджеты GitLab для Windows 10/11 x64 и Ubuntu 24.04 LTS amd64.

## Запуск

### Windows

Откройте `release/PipelineDesk-win32-x64/PipelineDesk.exe`. Установка и Node.js не нужны. Перемещайте всю папку приложения целиком.

Если вы скачали исходники с GitHub, сначала соберите приложение на Windows: установите Node.js, выполните `npm ci`, затем `npm run package`. Готовый EXE появится по указанному пути.

### Ubuntu 24.04 LTS

Скачайте `.deb` из артефакта `pipeline-desk-ubuntu-amd64` успешного запуска [Desktop CI](https://github.com/B-a-t-0-n/pipeline-desk/actions/workflows/desktop.yml) или соберите его из исходников. Установите через APT, чтобы также установить зависимости:

```sh
sudo apt install ./pipeline-desk_1.0.0_amd64.deb
pipeline-desk
```

Приложение также появится в меню приложений. Node.js для установленной версии не нужен. Обновление выполняется установкой нового `.deb` той же командой; пользовательские данные сохраняются. Удаление: `sudo apt remove pipeline-desk`.

На рабочем столе Wayland приложение использует XWayland: это необходимо для закрепления поверх окон, изменения размеров при переключении вида и восстановления положения. Пакет устанавливает зависимость `xwayland`; нативный Wayland для этих функций не поддерживается. В сеансе Xorg используется X11. [Ограничения Electron](https://www.electronjs.org/docs/latest/api/browser-window#platform-notices).

Крестик общей панели сворачивает её в панель задач, поэтому доступ сохраняется и без расширения трея GNOME. Значок трея дополнительно работает при наличии AppIndicator; расширение `gnome-shell-extension-appindicator` можно установить отдельно. Полностью завершить приложение можно кнопкой **Выйти** внизу общей панели или через меню трея. Закрытые отдельные виджеты не открываются повторно при следующем запуске.

Для токена требуется разблокированное системное хранилище секретов: в Ubuntu это GNOME Keyring. Небезопасный резервный режим `basic_text` не используется. При автоматическом входе в Ubuntu может потребоваться разблокировать связку ключей вручную в приложении «Пароли и ключи». Зашифрованный токен Windows нельзя перенести на Linux: подключите GitLab заново.

Пакет устанавливает профиль `/etc/apparmor.d/pipeline-desk`, разрешающий создание пространств имён установленному исполняемому файлу `/opt/pipeline-desk/pipeline-desk`. Это позволяет использовать sandbox Chromium при ограничениях Ubuntu 24.04; профиль не является дополнительной файловой песочницей. Пакет не отключает sandbox и не меняет системный `sysctl`. [AppArmor в Ubuntu](https://documentation.ubuntu.com/security/security-features/privilege-restriction/apparmor/).

### Подключение GitLab

1. Нажмите **Подключить GitLab**.
2. Сервер уже заполнен. Нажмите **Получить токен**, создайте персональный токен с правом **read_api** и вставьте его один раз. Вход сохраняется; адрес меняется через **Изменить**.
3. Отметьте нужные проекты в списке и нажмите **Добавить**. Есть поиск и загрузка следующей страницы. Через **По ссылке** можно указать отдельную ветку; без неё отслеживается последний пайплайн проекта среди всех веток.
4. Нажмите значок булавки на карточке: откроется отдельный виджет поверх окон. Перемещайте его за название проекта; размер меняется за края окна.

Булавка внутри виджета переключает режим поверх окон. Значок слоёв открывает общую панель. Положение, размер и открытые виджеты сохраняются. В Windows крестик общей панели скрывает её в трей, в Ubuntu — сворачивает в панель задач. Завершение — кнопка **Выйти** в общей панели или меню иконки в трее → **Выйти**.

В общей панели можно переключить карточки/список, светлую/тёмную тему и фильтр статуса. Клик по номеру пайплайна или этапу открывает задания. История расположена от старых запусков слева к новым справа. Пайплайн и задания открываются в браузере на подключённом GitLab.

Третий переключатель вида в общей панели включает **компактные строки** без подписи ветки. Вверху каждого виджета есть выбор: **Строка**, **Стадии**, **Подробно**. В режиме **Стадии** под каждым проектом видны все этапы с названиями: длинные названия и цепочки переносятся. Нажатие на этап открывает задания. Вид и высота окна для каждого режима сохраняются. Значок внешней ссылки открывает репозиторий.

## Группы

Нажмите **+ Группа**, отметьте состав и нажмите **Создать**. Название необязательно.

- **Проекты** — отдельные репозитории, включая ещё не добавленные в панель.
- **Группы GitLab** — доступные группы и подгруппы с полным путём. Опция **Включая подгруппы** включена по умолчанию.
- **Мои группы** — объединение существующих групп приложения в новую. Можно смешивать все три вида источников; исходные группы сохраняются.

Выберите группу в верхней строке и нажмите **Виджет группы**. Все её репозитории откроются в одном окне поверх остальных; новые виджеты групп показывают стадии по умолчанию. Значок карандаша меняет состав и название; там же можно удалить группу. Проекты при удалении группы остаются в общей панели.

Состав групп GitLab синхронизируется раз в минуту и по кнопке **Обновить**. Новые проекты появляются, вышедшие из группы исчезают из её виджета. При недоступности GitLab сохраняется предыдущий состав с ошибкой. Проекты, встречающиеся в нескольких источниках, не дублируются; отдельные настройки веток сохраняются как отдельные строки. Объединённая группа получает копию ручного состава исходных групп и сохраняет автоматическую синхронизацию их источников GitLab. Операции с группами приложения не изменяют GitLab.

Интервал обновления: 15, 30 или 60 секунд, в настройках → **Дополнительно**. Ветка и последние пайплайны обновляются автоматически. Если GitLab недоступен, последние данные остаются с явной ошибкой и временем получения. Лимит запросов вызывает паузу перед повтором.

## Данные

Первый запуск показывает **демо**, а не актуальное состояние проектов. Пример `supply-demand-backend` основан на предоставленном скриншоте; остальные проекты и статусы иллюстративные. Подключение к реальному GitLab заменяет демонстрацию вашими проектами.

Подключение, проекты, группы, параметры обновления и настройки окон хранятся локально в SQLite: `%APPDATA%/Pipeline Desk/config.sqlite` в Windows и `~/.config/Pipeline Desk/config.sqlite` в Ubuntu (либо внутри `XDG_CONFIG_HOME`, если он задан). Устанавливать SQLite отдельно не нужно: приложение использует встроенный `node:sqlite`. Таблица `settings` содержит параметры, таблица `credentials` — зашифрованный токен в BLOB. Изменения записываются одной транзакцией.

Токен шифруется через Electron safeStorage: Windows DPAPI в Windows, системная связка ключей в Ubuntu. Он не передаётся обратно в интерфейс. При первом запуске после обновления данные автоматически переносятся из `settings.json`, включая уже зашифрованный токен. Старый JSON остаётся неизменной резервной копией; после переноса приложение читает и обновляет только SQLite. Отключение удаляет токен из активной базы. При ошибке открытия базы приложение сохраняет исходные файлы и сообщает об ошибке.

Для резервной копии закройте приложение и сохраните всю папку данных приложения (`%APPDATA%/Pipeline Desk` в Windows или `~/.config/Pipeline Desk` в Ubuntu). В Linux для расшифровки также нужна исходная системная связка ключей; одной копии SQLite недостаточно. Во время работы рядом с базой могут находиться служебные файлы `config.sqlite-wal` и `config.sqlite-shm`. Файлы базы и авторизации исключены из Git.

Приложение выполняет только GET-запросы к GitLab. Запуск, отмена, повтор заданий и деплой не реализованы.

Если в настройках приложения задан `netrcPath`, оно читает запись `machine` только для выбранного сервера. В поле `password` нужен API-токен, обычный пароль GitLab не подходит. Для `login oauth2` используется Bearer, иначе PRIVATE-TOKEN. Запись `default` игнорируется. После успешного импорта токен сохраняется зашифрованным. При первом подключении файл используется автоматически; после ошибки повторные попытки останавливаются. Исправленный файл можно перечитать кнопкой **Повторить из .netrc**. Содержимое файла и его путь не передаются в интерфейс.

Поддерживается один GitLab-сервер за раз, в том числе сервер в подпапке. При смене сервера список проектов заменяется; при отключении токен и список удаляются. Для корпоративного GitLab может потребоваться VPN и доверенный системой сертификат.

Этапы группируются по заданиям и упорядочиваются по первым ID заданий, включая повторные запуски. Для необычных конфигураций с динамически создаваемыми этапами порядок может отличаться от графа GitLab. Дочерние пайплайны показаны как bridge-задания; детали открываются в GitLab.

## Разработка

Нужен Node.js 22.12 или новее; CI использует Node.js 24.

```powershell
cd pipeline-desk
npm ci
npx --no-install install-electron
npm start
```

```powershell
npm test
npm run test:ui
node tests/setup.mjs
node tests/groups-ui.mjs
node tests/widget-views.mjs
node tests/full-group-layout.mjs
node tests/storage-electron.mjs
npm run package
npm run preview
```

Предпросмотр: `http://127.0.0.1:4317/ui/index.html`. В браузере доступны демонстрация и просмотр виджета; настоящее закрепление и GitLab работают в настольном приложении Windows/Ubuntu.

Проверки API используют фикстуры: повторные задания, optional failures, manual/canceled, пагинация, read-only запросы, неверный токен и rate limit. Electron-проверки охватывают интерфейс, настоящие окна, закрепление, восстановление, защищённое сохранение токена, импорт .netrc, поиск и массовый выбор проектов. Успешное подключение к реальному GitLab требует действующего API-токена.

### Сборка и проверки Ubuntu

```sh
npm ci
npx --no-install install-electron
npm test
npm run package:linux
sudo apt install ./release/pipeline-desk_1.0.0_amd64.deb
```

Сборка выполняется на Linux x64 с `dpkg-deb`; результат — `release/pipeline-desk_1.0.0_amd64.deb`. Портативный каталог `release/PipelineDesk-linux-x64` — промежуточный результат сборки. На Ubuntu 24.04 запускайте установленную версию, чтобы применялся её профиль AppArmor.

Для разработки через `npm start` на Ubuntu 24.04 администратору может потребоваться отдельный профиль AppArmor с точным абсолютным путём к `node_modules/electron/dist/electron` (образец есть в `.github/workflows/desktop.yml`). Не используйте `--no-sandbox` и не отключайте ограничение user namespaces глобально.

Для полного набора проверок установите `xvfb`, `openbox`, `dbus-x11`, `gnome-keyring`, `desktop-file-utils`, `apparmor-utils`, `x11-utils`; затем:

```sh
npx playwright install --with-deps chromium
sh scripts/test-linux.sh
```

Скрипт создаёт отдельные Xvfb/D-Bus-сеанс и тестовую связку ключей; требует установленный `.deb` и разрешённый AppArmor запуск Electron из исходников. Проверяются реальные окна, сворачивание и восстановление, закрепление, закрытие виджетов, сохранение токена и миграция SQLite, а также метаданные и запуск установленного пакета. `npm run test:desktop` запускает тот же набор UI-проверок в уже подготовленном графическом окружении и сам поднимает сервер предпросмотра. На Windows используйте эту команду напрямую. GitLab во всех этих проверках заменён фикстурами.

API: [GitLab pipelines](https://docs.gitlab.com/api/pipelines/), [GitLab jobs](https://docs.gitlab.com/api/jobs/), [GitLab groups](https://docs.gitlab.com/api/groups/), [personal access tokens](https://docs.gitlab.com/user/profile/personal_access_tokens/), [Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage), [Node.js SQLite](https://nodejs.org/api/sqlite.html).
